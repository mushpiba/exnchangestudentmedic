# NARU · 나루

인하대 유학생을 위한 모국어 의료생활 PWA. 내 언어로 증상을 고르면 접수대에 보여줄 한국어 카드가 만들어지고, 한국 약 상자를 찍으면 어떤 약인지 내 언어로 알려준다. 같은 학교 유학생끼리 병원·약국 경험을 나누는 커뮤니티가 있다.

## 실행

Node.js 22.12 이상.

```bash
npm ci
npm run dev        # 개발 서버
npm test           # 번역 누락·콘텐츠 참조·약 분석·카드 구성 테스트
npm run build      # 타입 검사 + 빌드 (dist/)
npm run preview    # 서비스 워커 포함 빌드 확인
```

main에 push하면 GitHub Actions가 Pages에 배포한다.

## 디자인

2026-11-18 `/design-compare` 5안 비교 후 결정: 색·앱 틀·접수 전표 모양은 unslop 안, 선택 체크(체크 상자 + 형광펜 노랑)와 답변 도장은 impeccable 안. 규칙은 `src/style.css` 머리말에 있다.

- 회색 단계 + 브랜드 초록 하나. 직원에게 보이는 한국어는 늘 종이 전표(티켓 홈·절취선) 위에.
- 노랑 = 고른 것·답한 것. 빨강은 응급(119, 응급 신호, 응급실 안내)에만. 중복 복용·전문의약품 경고는 주황 계열.
- 375px 기준(360px까지 확인), 본문 양옆 여백 20px, 글자 16px 이상, 직원 카드 핵심 값 28px(크게 보기 32px), 터치 48px 이상. 하단 탭과 아이콘 아래 라벨만 14px. 탭 폭은 라벨의 가장 긴 낱말보다 좁아지지 않게 하고, 그래도 넘치는 언어가 생기면 낱말 안에서 줄을 바꾼다. 16개 언어 모두 360px에서 낱말을 끊지 않고 들어가는 것을 확인했다(러시아어 '커뮤니티'는 Форум, 프랑스어 '학교'는 Campus, 스페인어 '약'은 Medicinas, 프랑스어 '병원·약국'은 Où se soigner로 줄임).
- 하단 탭: 홈 · 증상 카드 · 약 · 병원·약국 · 학교. 두 수익 축(대학 운영 계약, 의원·약국 다국어 안내)이 각각 '학교'와 '병원·약국' 탭이다. 게시판은 같은 학교 공간이라 '학교' 탭 안에 둔다.

## 코드 구조

```
src/
  main.tsx                 첫 언어를 불러온 뒤 렌더
  app/App.tsx, router.ts   상단바·하단 탭·해시 라우팅
  i18n/
    index.tsx              t()(학생 언어)·tk()(한국어)·variants()(검색용) 제공. 언어팩은 언어별로 나눠 지연 로드
    locales.ts             16개 언어(학생용 이름, 직원용 한국어 이름, RTL)
    messages/<locale>.json NARU 자체 문구 (ko-KR이 원문)
    simtomi/<locale>.json  심토미 1.3.19 언어팩에서 가져온 의료 어휘 152개 (13개 언어)
  content/                 증상·질환·성분·기관·학교 연락처 데이터 (문구는 키로만 참조)
  state/card.tsx           증상 카드 상태와 한국어 카드 구성
  lib/medMatch.ts, ocr.ts  약 성분 인식(퍼지 매칭 포함), 기기 내 OCR
  campus/                  커뮤니티·버디 API. preview(탭 메모리) / live(Supabase) 두 구현
  pages/                   화면
scripts/import-simtomi.mjs 심토미 언어팩 → src/i18n/simtomi
supabase/pilot.sql         학교 연동 스키마
```

문구 우선순위는 `messages/<locale>` → `simtomi/<locale>` → 영어 → 한국어. 우즈베크어·카자흐어·키르기스어는 심토미에 없어 심토미 키까지 `messages/`에 번역해 두었다. `npm test`가 16개 언어 모두 누락·자리표시자 불일치가 없는지, 코드에서 쓰는 키가 실제로 있는지 검사한다.

## 콘텐츠 출처와 검수 상태

- **심토미 어휘**: 증상 분류 20개, 진료과 36개, 통증 척도, 문진 질문, 일반의약품 분류·제형, 주의 문구. `npm run import:simtomi`로 다시 가져온다.
- **대화형 문진 (2026-11-19)**: 심토미 1.3.19 문진 데이터(증상 261개, 질문 1,021개)를 `scripts/extract-simtomi-intake.py`로 `data/simtomi/`에 옮기고, `npm run build:intake`(`scripts/build-intake.mjs`)가 NARU 규칙(`scripts/intake-rules.mjs`: 데이터 오류 수정, 응급 신호 질문 약 75개, 데이터에 없는 연관 증상 규칙)을 적용해 `src/intake/data/bank.json`과 한국어 원문 `src/intake/text/ko-KR.json`을 만든다. 증상 시작 질문에서 도달하는 질문만 남기며, 질환 질문 표본(나이 12·26·70세)은 규칙으로 쓰지 않는다. Science Photo Library 사진 46장은 저작권 때문에 넣지 않았다. 근거와 수정 내역: `../../reports/문진데이터_의학점검_2026-11-19.md`.
  - 번역: 15개 언어를 Claude Sonnet이 번역하고, 언어마다 독립 검토(안전 문구 전부 + 표본)를 거쳤다. 원어민·의료진 검토 전이다. `node scripts/check-intake-i18n.mjs`가 누락·자리표시자·남은 한글·응급 번호를 검사하고 `npm test`에 포함된다.
  - **법적 확인 필요**: 주증상에 따라 저장된 질문을 보여 주는 이 구조와 심토미 데이터 사용이 메디아크 특허 제10-2849580호 청구항에 해당하는지 배포 전에 확인해야 한다.
- **증상 세부 문항 (이전 방식)**: `src/content/details.ts` 50문항(가족력·생활 10문항 포함), 문구 약 350개. 일반 임상 문진(양상·시점·악화 요인·퍼짐·위험 신호)을 바탕으로 새로 작성. 심토미 앱 코드에서 확인한 것은 문항 형식(예/아니요, 점수, 신체 그림)과 흐름뿐이고, 문항 내용은 심토미 서버(`symptomDb.json`)에 있어 가져오지 않았다. 주증상에 따라 저장된 문항을 보여주는 구조는 메디아크 특허 제10-2849580호 청구항과 대조해 구현 범위를 정한다.
- **문항 보강에 참고한 자료** (2026-11-18): 문장은 옮기지 않고 무엇을 묻는지만 참고해 NARU 말투로 새로 썼다.
  - DDXPlus (Fansi Tchango et al., NeurIPS 2022; Mila), 영어판 evidence 223개, **CC BY 4.0** (figshare 기록 확인). 통증 시작·악화 요인, 기침 발작·흡기 시 고음, 변·방귀 안 나옴, 복시·경련, 흡연·음주·해외 방문·접촉·면역저하 등. 이 데이터로 질환을 추정하지 않는다(의료기기 해당 가능성, 특허 청구항의 진단 단계).
  - 다언어 의료문진표 (NPO법인 국제교류하티항남대·가나가와국제교류재단, kifjp.org/medical): 내과·산부인과·정신과·치과 항목 구성 참고(수유, 수혈, 현재 치료, 통역 동행, 환청·감시감, 치과 마취·발치·원하는 치료). 영리 목적 사용 금지라 문구와 번역은 쓰지 않았다.
- **NARU 자체 콘텐츠**: 세부 증상 61개, 질환 정보 17개, 응급·긴급 신호 21개, 성분 사전 61종, 직원 문장 63개. 한국어 원문 작성 후 15개 언어로 LLM 번역한 **초안**이다.
- **제품 40종**: 식약처 의약품안전나라 검색 결과의 주성분·품목기준코드로 등록(2026-11-18 확인). 한 브랜드에 성분이 다른 제품이 섞여 있어(게보린정↔게보린소프트, 탁센 나프록센↔이부프로펜, 판콜에스↔판콜아이 덱시부프로펜, 케토톱↔케토톱액티브 플루르비프로펜) 제품명 단위로만 성분을 연결한다. 브랜드명만 보이면 성분을 추정하지 않고 제품을 고르게 안내한다.
- **한국 의료 안내** (`src/content/guide/`): 숫자는 `figures.ts`에 연도·출처와 함께 둔다. OECD 『Health at a Glance 2025』(StatLink 자료, OECD 평균은 OECD가 낸 단순 평균), 세계은행 WDI API(2026-11-19 수집, CC BY 4.0, 나라별 최신 값), 대만은 세계은행에 없어 대만 위생복리부·내정부 통계(정의가 달라 그래프에 주석). 한국 제도(보험료·본인 부담·진료의뢰서·응급실 90%·편의점 상비약·공공심야약국)는 2026년 11월 시행 법령(law.go.kr)과 NHIS·HIRA·보건복지부 자료로 확인했다. 감기 진료 총액(약 8,000~9,000원)은 공식 요금으로 NARU가 계산한 예상치라고 본문에 밝혔다. 확인하지 못한 것(119 무료의 소방청 공식 문서, 응급의료관리료 현재 금액, 진료 시간 9분 등)은 쓰지 않았다. 나라별 차이점은 WHO·유럽 보건의료 관측소·각국 정부·논문에서 출처를 확인한 것만 넣었고, 출처는 `home-sources.json`. 글은 한국어 원문 → 14개 언어 LLM 번역 초안이며, 각 언어 파일에는 자기 나라 비교만 들어 있다(한국어·영어는 15개국 전부).
- **외국 약 79종** (`src/content/foreign-meds.json`): 러시아·CIS 공통(vidal.ru·rlsnet.ru), 중국(drugs.dxy.cn 설명서), 베트남(제조사·약국 등록 정보), 일본(PMDA), 영국(emc·제조사), 미국(DailyMed), 네팔(사노피 문서)에서 제품마다 성분·함량과 출처 URL을 확인(2026-11-19). 같은 이름도 나라마다 성분이 달라(Panadol Cold & Flu, Theraflu, 중국 泰诺 감기약 ↔ 미국 Tylenol) 나라별 제품으로 나눴다. 몽골·우즈베크·카자흐·키르기스는 러시아 등록 정보를 함께 쓰는 것으로 표시했고 나라별 개별 확인은 하지 않았다. 파키스탄 제품은 공식 출처를 못 찾아 넣지 않았다. NARU 성분 사전에 없는 성분(메타미졸·드로타베린·우미페노비르 등 36종)은 국제일반명으로만 보여 주고 약사에게 확인하게 한다.
- 현장 사용 전 필요한 것: 언어별 원어민 확인, 의료진·약사의 의미 검수(부정·좌우·수치·응급 문구), 성분 사전 약사 검토, 실기관 응대 언어 현장 확인.

## 개인정보

- 증상 카드·약 사진·복용 약은 탭 메모리에만 있고 서버로 보내지 않는다. 새로고침하면 사라진다.
- 학생이 직접 쓴 말(내 말로 쓴 증상·하고 싶은 말·알레르기·복용 약 원문)은 학생이 '한국어로 번역하기'를 누를 때만 임시 번역 서버(MyMemory)로 보내 번역하고, 결과를 카드(탭 메모리)에 저장해 직원 카드에서 원문 위에 보여 준다. 누르기 전에 '외부 서버로 전송되고 저장될 수 있으니 이름·전화번호·학번은 쓰지 말라'는 안내를 보여 준다. 누르지 않으면 브라우저 내장 기기 안 번역(크롬·엣지 데스크톱)이 있을 때만 번역하고, 없으면 원문만 보여 준다.
- 지도를 열면 지도 그림을 OpenStreetMap 타일 서버에서 받는다(접속 IP가 전달됨).
- 약 사진 OCR은 브라우저 안에서 실행된다. 첫 사용 때 OCR 엔진과 한국어·영어 모델을 CDN에서 내려받는다(이후 브라우저 캐시).
- 글꼴(IBM Plex Sans·KR·Arabic)은 Google Fonts에서 불러온다. 오프라인이면 기기 글꼴로 보인다.
- localStorage에는 선택한 언어만 저장한다.
- 커뮤니티·버디는 연동 모드에서만 서버에 저장된다. 증상 카드 내용은 자동으로 게시판에 복사되지 않는다. 글쓰기 전에 전화번호·이메일 패턴을 경고한다.

## 공공데이터포털 키 발급 (병원·약국 목록용)

1. [data.go.kr](https://www.data.go.kr)에 가입·로그인한다(개인 회원 가능).
2. 검색창에서 다음 API를 찾아 각각 **활용신청**한다. 활용 목적은 예: "외국인 유학생 의료기관 안내 서비스 개발".
   - 건강보험심사평가원_병원정보서비스 (병원·의원 이름, 종별, 주소, 좌표, 전화)
   - 건강보험심사평가원_약국정보서비스 (약국)
   - 선택: 건강보험심사평가원_의료기관별상세정보서비스 (진료과목·진료시간), 국립중앙의료원_전국 응급의료기관 정보 조회 서비스 (응급실)
3. 개발계정은 대부분 자동 승인된다. **마이페이지 → 데이터 활용 → Open API → 활용신청 현황**에서 '일반 인증키'(Encoding/Decoding)를 확인한다. 한 계정의 키 하나가 승인된 API 전부에 쓰인다. 메뉴 이름은 조금 다를 수 있다.
4. 키를 채팅이나 코드에 붙여넣지 않는다. GitHub 저장소 **Settings → Secrets and variables → Actions → New repository secret**에 이름 `DATA_GO_KR_KEY`, 값은 Decoding 키로 등록한다.
5. 그다음 배포 때 Actions가 키로 인하대 주변 목록을 받아 앱 데이터로 만들도록 연결한다(키는 사이트에 노출되지 않는다). 이 연결은 다음 작업이다.

## 학교 연동 (Supabase)

공개 Pages 배포는 DB 설정이 없는 **검토 모드**다. 커뮤니티에는 예시 글이 보이고, 쓴 글·버디 신청은 이 탭에만 남는다.

연동 모드:

1. Supabase 프로젝트에 `supabase/pilot.sql`을 한 번 적용한다. 테이블은 RLS가 켜져 있고 정책이 없어 직접 읽거나 쓸 수 없다. 모든 동작은 호출자의 `auth.uid()`로 학교·역할을 확인하는 함수(RPC)를 거친다.
2. 학교 확인을 마친 이용자를 Auth에 등록하고, `campus_members`에 같은 UUID·캠퍼스 키·역할(student/buddy/operator)·표시 이름을 넣는다.
3. Auth 메일 템플릿에 숫자 OTP(`{{ .Token }}`)를 넣는다.
4. 저장소 Actions Variables에 `VITE_CAMPUS_URL`, `VITE_CAMPUS_PUBLIC_KEY`(브라우저용 publishable 키)를 설정하고 배포한다. 서비스 역할 키는 서버 관리자 전용이다.

연동 시 동작: 같은 학교 글만 보임, 익명 번호는 글마다 첫 댓글 순서로 매김(작성자 ID는 응답에 포함하지 않음), 공감 10개 이상이 HOT, 신고는 운영자 큐(`moderation_queue`)로, 운영자는 글·댓글 숨김. 버디는 운영자가 같은 학교 버디를 배정 → 버디 수락/거절 → 학생 또는 버디가 완료. 학생은 자기 신청, 버디는 배정된 신청, 운영자는 학교 전체를 본다. 로그인 세션은 sessionStorage에 있어 새로고침에는 유지되고 탭을 닫으면 끝난다.
