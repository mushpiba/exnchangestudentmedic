# Inha Care
인하대 유학생을 위한 모국어 의료생활 PWA 검토판. Chrome에서 URL로 바로 열거나 홈 화면에 설치할 수 있다. iPhone은 Safari의 공유 메뉴에서 홈 화면에 추가한다.

## 실행
Node.js 22.12 이상에서 `npm ci`, `npm run dev`로 개발한다. `npm run build` 후 `npm run preview`에서 설치용 manifest와 서비스 워커를 포함한 빌드를 확인한다. main에 push하면 GitHub Actions가 Pages에 배포한다.

## 검토 경로
1. 홈에서 언어를 고르고 증상 카드를 만든다. 입력 중 언어를 바꾼 뒤 한국어 카드에서 원래 선택을 확인한다.
2. 기관 찾기에서 기관 유형과 응대 언어를 바꾼다. 인천시 공식 목록의 실제 병원 세 곳에서 전화와 길찾기를 연다. 언어별 예시 기관은 실제 운영 정보와 분리했다. 외부 지도는 인하대 주변 실기관 검색으로 연결된다.
3. 약 포장 사진을 선택하고 문자 인식을 실행한다. 인식 결과를 직접 정정한 후 약사에게 제시한다. OCR은 브라우저에서 실행되며 첫 사용에는 라이브러리와 언어 모델 다운로드가 필요하다. 현재 인식 모델은 한국어·영어·러시아어다. 검토용 식약처 품목 한 건(202106092)에 한해 단일 성분·함량·제형 일치 여부를 대조한다. 품목 출처를 열어 직접 확인할 수 있다.
4. 첫 방문 안내를 체크하고 버디 일정·게시글 작성을 검토한다. 검토판의 동행과 게시글은 탭 메모리에만 남는다. 학교에 신청 또는 전송되지 않는다.
5. 첫 방문 후 온라인 상태에서 서비스 워커 설치가 끝나면 네트워크를 끊고 다시 연다. 공통 안내와 문진은 작동하고 외부 지도·공식기관 링크·최초 OCR 모델 다운로드에는 연결이 필요하다.

## 콘텐츠와 데이터
13개 로케일의 기본 단어를 심토미 1.3.19 언어팩에 대조해 사용했다. 의료 문맥과 불일치하는 번역은 덮어쓰며 신규 화면·중앙아시아 3개 언어는 LLM 번역 초안이다. 용도는 사용성 검토이며 언어별 임상 검수, 자료 이용 조건의 확정, 실기관 조사와 운영 담당자 확보가 현장 출시 전 필요하다. 언어 리소스는 src/data, 문맥 교정은 src/i18n.ts에 있다. 자격증명·APK·이미지 자산은 배포하지 않는다.

언어 선택만 localStorage에 남는다. 증상·사진·복약 정보·방문 체크·게시글은 페이지를 새로고침하면 사라진다. HTTP 요청과 정적 캐시에 환자 기록을 넣지 않는다. 공개 저장소나 GitHub Issues에 개인 건강정보를 올리지 않는다.

## 다음 배포 선택지
GitHub Pages는 정적 검토판의 기본 배포다. PR별로 다른 주소가 필요하면 Cloudflare Pages의 Git 연동(명령 npm run build, 출력 dist)이 적합하다. 실제 학교 인증·공유 게시판·버디 배정에는 접근 제어가 있는 서버와 DB가 필요하다.

## 학교 계정 연동
공개 Pages 배포는 DB 설정이 없는 검토 모드다. 연동 모드는 Supabase Auth와 Postgres를 사용한다. 관리하는 프로젝트에서 supabase/pilot.sql을 한 번 적용하고 학교 확인을 마친 이용자를 Auth에 등록한 뒤 campus_members에 같은 사용자 UUID, 캠퍼스 키, student/buddy/operator 역할을 부여한다. Auth 메일 템플릿에 숫자 OTP({{ .Token }})를 넣는다. GitHub 저장소 Actions Variables의 VITE_CAMPUS_URL, VITE_CAMPUS_PUBLIC_KEY에 해당 프로젝트 URL과 브라우저용 publishable 키를 설정한 후 배포한다. 서비스 역할 키는 서버 관리자 전용이다.

연동 시 게시판은 학교별 조회·작성·본인 글 삭제·신고·운영자 숨김을 지원한다. 버디 신청은 운영자가 같은 학교 버디를 선택해 배정하고, 버디는 수락·거절, 신청자는 취소 또는 동행 완료를 기록한다. 일정은 UTC로 보관하고 이용자 현지 시간으로 표시한다. 서버에는 동행 요청의 언어·일시만 보낸다. 증상 카드와 약 포장은 전송 대상에서 제외한다. 실제 운영자가 공지를 마련하고 신청자와 버디에게 장소·연락 방법을 전달해야 한다.

음성 입력은 지원 브라우저에서 이용자가 기기의 음성 처리 안내를 확인한 뒤 시작한다. 받아쓴 원문을 수정한 후 카드에 반영한다. 기기별 지원 언어는 다를 수 있다.
